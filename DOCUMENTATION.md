## 1. Обзор проекта

**«Центр Пиротехники»** — одностраничный лендинг (single-page application) для компании, занимающейся продажей сертифицированной пиротехники и организацией пиротехнических шоу. Сайт ориентирован на русскоязычную аудиторию (Россия).

### Назначение

- Презентация ассортимента пиротехники (салюты, фейерверки, петарды, хлопушки, бенгальские огни, римские свечи, фестивальные шары).
- Продвижение услуг: продажа, доставка, профессиональный запуск фейерверков, организация шоу под ключ.
- Приём заявок на бронирование шоу и обратной связи от клиентов.
- Демонстрация портфолио, отзывов, команды и галереи работ.

### Ключевые характеристики

| Параметр | Значение |
|---|---|
| Тип приложения | SPA (Single Page Application) |
| Язык интерфейса | Русский |
| Количество страниц | 2 (главная Index + 404 NotFound) |
| Количество секций главной | 14 |
| Бэкенд / база данных | Не используется (все данные — статичные в памяти) |
| Аутентификация | Отсутствует |
| Маршрутизация | React Router (хэш-навигация по секциям) |
| Состояние форм | Локальное (useState), без серверной отправки |

## 4. Архитектура приложения

### 4.1. Точка входа

**`src/main.tsx`** — рендерит `<App />` в DOM-элемент `#root`, импортирует глобальный CSS.

### 4.2. Корневой компонент

**`src/App.tsx`** оборачивает приложение в провайдеры:

```
QueryClientProvider (TanStack Query)
  └── TooltipProvider (Radix Tooltip)
       ├── Toaster (shadcn/ui toast — из use-toast)
       ├── Sonner (sonner toasts)
       └── BrowserRouter (React Router)
            └── Routes
                 ├── "/" → <Index />
                 └── "*" → <NotFound />
```

> **Примечание:** `QueryClient` инициализирован с дефолтными настройками и не используется для запросов к API. Это подготовка к будущему подключению бэкенда.

### 4.3. Паттерн данных

Все данные сайта (товары, услуги, отзывы, портфолио, галерея, FAQ, команда, контакты, навигация) хранятся в **едином модуле** `src/data/siteData.ts` и экспортируются как константа `siteData`. Это упрощает поддержку контента, но означает, что данные статичны и не сохраняются между сессиями.

### 4.4. Коммуникация с пользователем

Формы (бронирование, контакты, подписка) **не отправляют данные на сервер**. При сабмите показывается toast-уведомление с подтверждением, а поля сбрасываются. Для реальной работы форм требуется подключение бэкенда (например, Supabase или edge-функция).

### 5.3. Типографика

- Шрифт по умолчанию: системный (через Tailwind `font-sans`, явного `@font-face` нет).
- Заголовки: `font-bold`, размеры от `text-lg` до `text-7xl`.
- Основной текст: `text-sm` / `text-base`, `leading-relaxed` для многострочных абзацев.
- Используется 3 веса шрифта: normal (400), medium (500), bold (700).

### 5.4. Скругления и отступы

- Базовый радиус: `0.75rem` (12px).
- Система отступов: Tailwind по умолчанию (база 4px).
- В секциях используется `py-20` (вертикальный отступ 80px) и `container mx-auto px-4` (горизонтальное центрирование).

### 5.5. Tailwind-конфигурация

**`tailwind.config.ts`**:
- `darkMode: ["class"]` — тёмная тема по классу `.dark`
- `content` — сканирование `./src/**/*.{ts,tsx}`, `./pages/**`, `./components/**`, `./app/**`
- `container` — центрирование, padding 2rem, максимальная ширина 1400px на `2xl`
- `container.screens.2xl: "1400px"` — максимальная ширина контейнера
- Плагины: `tailwindcss-animate`, `@tailwindcss/typography`
- Кастомные keyframes: `accordion-down`, `accordion-up`
- Все цвета привязаны к CSS-переменным через `hsl(var(--token))`

### Утилиты

**`src/lib/utils.ts`** — функция `cn()`:
```typescript
export function cn(...inputs: ClassValue[]) {
  return twMerge(clsx(inputs));
}
```
Объединяет классы через `clsx` и удаляет конфликтующие Tailwind-классы через `tailwind-merge`. Используется во всех UI-компонентах и секциях.

## 7. Секции страницы (landing-блоки)

Главная страница состоит из 14 секций, каждая вынесена в отдельный компонент в `src/components/sections/`.

### 7.1. Hero — `Hero.tsx`

**Назначение:** Главный экран (hero section), первое впечатление.

- Полноэкранный фон (`min-h-screen`) с изображением фейерверка.
- Тёмный градиентный оверлей для читаемости текста.
- Бейдж «№1 Пиротехнический центр в России» с градиентом огня.
- Заголовок: «Зажгите небо над вашим праздником» (с градиентным текстом).
- Описание услуги и целевых аудиторий (свадьбы, корпоративы, городские праздники).
- Две CTA-кнопки: «Выбрать пиротехнику» (→ `#catalog`), «Забронировать шоу» (→ `#booking`).
- Блок статистики: 4 карточки с показателями (15 лет, 5000+ товаров, 1200+ шоу, 50 тыс клиентов).
- Анимация «Листайте вниз» со стрелкой (`animate-bounce`).

### 7.2. Categories — `Categories.tsx`

**Назначение:** Витрина категорий товаров.

- Сетка из 6 карточек категорий (1/2/3 колонки).
- Каждая карточка: изображение с затемнением, иконка в градиентном кружке, название, количество товаров.
- Иконки: `Sparkles`, `Flame`, `Zap`, `PartyPopper`, `Lightbulb`, `Rocket`.
- Hover-эффект: подъём карточки (`hover:-translate-y-2`) + зум изображения.
- Фон секции: `bg-muted/30`.

### 7.3. Catalog — `Catalog.tsx`

**Назначение:** Каталог товаров с фильтрацией по категориям.

- **Tabs** для фильтрации по категориям: «Все», «Салюты», «Римские свечи», «Петарды», «Хлопушки», «Бенгальские огни», «Фестивальные шары», «Наземные».

## 13. Адаптивность

### Брейкпоинты (Tailwind по умолчанию)

| Брейкпоинт | Ширина | Использование |
|---|---|---|
| (по умолчанию) | 0–639px | Мобильные — 1 колонка |
| `sm` | ≥640px | Малые планшеты |
| `md` | ≥768px | Планшеты — 2 колонки, появление кнопок карусели |
| `lg` | ≥1024px | Десктопы — 3 колонки, появление горизонтальной навигации |
| `xl` | ≥1280px | Большие экраны — 4 колонки (каталог товаров) |
| `2xl` | ≥1400px | Максимальная ширина контейнера (1400px) |

### Адаптивные решения

- **Header:** навигация переключается на бургер-меню (Sheet) ниже `lg`.
- **Сетки:** `grid-cols-1 sm:grid-cols-2 lg:grid-cols-3` — универсальный паттерн.
- **Каталог:** `grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 xl:grid-cols-4`.
- **Карусели:** кнопки навигации скрыты ниже `md` (`hidden md:flex`).
- **Бронирование:** двухколоночный макет на `lg+`, одна колонка на мобильных.
- **Hero:** заголовок масштабируется `text-4xl md:text-6xl lg:text-7xl`.
- **Статистика hero:** 2 колонки на мобильных, 4 на `md+`.
- **ShowTypes:** средняя карточка увеличена только на `lg` (`lg:scale-105`).
- **HowItWorks:** соединительные линии между шагами только на `lg`.

### Мобильное меню

Использует `Sheet` из shadcn/ui (на основе Radix Dialog). Выезжает справа, ширина 300px. Закрывается по клику на ссылку (через `SheetClose asChild`).

## 17. Безопасность

### 17.1. Текущее состояние

- **Нет бэкенда** — все данные статичны, нет риска SQL-инъекций или несанкционированного доступа к данным.
- **Нет аутентификации** — публичный сайт без личных кабинетов.
- **Формы не отправляют данные** — нет риска утечки персональных данных (но и нет реальной функциональности).
- **Изображения с внешнего CDN (Pexels)** — нет загрузки пользовательских файлов.
- **Нет обработки пользовательского контента** — нет риска XSS через пользовательский ввод (вводимые данные не рендерятся как HTML).

### 17.2. Потенциальные риски

| Риск | Описание | Уровень |
|---|---|---|
| Внешние скрипты | Два скрипта с `cdn.poehali.dev` — сторонний код | Низкий (платформенные) |
| Нет HTTPS-заголовков | Требуется настройка на уровне хостинга | Средний |
| Нет CSRF-защиты | Неактуально до реализации бэкенда | — |
| Нет валидации форм на сервере | Формы пока не отправляются | — |
| Телефон в коде | Контактный телефон захардкожен в `siteData` и в FAQ — неуязвимость, но неудобно для изменений | Низкий |

### 17.3. Рекомендации

- При подключении бэкенда: реализовать серверную валидацию всех форм, защитить API ключами/токенами.
- Добавить reCAPTCHA для форм бронирования и обратной связи.
- Настроить CSP-заголовки (Content Security Policy).
- При добавлении корзины — защищать транзакции и персональные данные.

## Приложение B. Паттерн маппинга иконок

В секциях `Categories`, `Advantages`, `Services` используется паттерн маппинга строковых имён иконок к компонентам lucide-react:

```typescript
const iconMap: Record<string, React.ComponentType<{ className?: string }>> = {
  BadgeCheck, Award, Truck, ShieldCheck, Boxes, Tags,
};

// В рендере:
const Icon = iconMap[adv.icon] ?? BadgeCheck; // fallback
```

Это позволяет хранить в `siteData` строки (имена иконок) и получать соответствующие React-компоненты.

## Приложение C. Система тостов

### Конфигурация

- **`src/hooks/use-toast.ts`** — редьюсер-паттерн с глобальным состоянием (модульная переменная `memoryState` + подписчики).
- **`TOAST_LIMIT = 1`** — одновременно отображается только 1 тост.
- **`TOAST_REMOVE_DELAY = 1000000`** — задержка удаления (очень большая, тосты закрываются вручную или по swipe).
- **Два рендера в App:**
  - `<Toaster />` (shadcn/ui, из `use-toast`) — используется в формах бронирования, контактов, каталога.
  - `<Sonner />` (sonner) — подключён, но не используется напрямую в коде секций.

### Использование

```typescript
const { toast } = useToast();
toast({
  title: "Заявка отправлена!",
  description: "Мы свяжемся с вами...",
});
```
